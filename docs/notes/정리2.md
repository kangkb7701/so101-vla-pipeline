# 프로젝트 아키텍처 및 모듈화 가이드 (OpenVLA 스타일 반영)

본 문서는 OpenVLA의 설계 철학을 참고하여, 현재 프로젝트를 학술 논문 수준으로 고도화하기 위한 구조적 가이드라인을 제시합니다.

---

## 1. 대학생 논문에서 OpenVLA 수준의 엄격함이 필요한가?

**결론: "구조의 정신"은 따르되, "구현의 복잡도"는 낮춰야 합니다.**

OpenVLA와 같은 거대 프로젝트의 엄격함이 필요한 이유는 수만 명의 사용자와 수십 명의 기여자가 있기 때문입니다. 대학생 논문 수준에서는 다음 두 가지만 챙기면 충분합니다.

1.  **실험 재현성**: "내가 설정(Config)만 바꾸면 누구나 똑같은 실험을 할 수 있는가?"
2.  **비교 용이성**: "IK를 RoLA로 바꿀 때, 기존 코드를 다 갈아엎지 않고 특정 모듈만 교체할 수 있는가?"

이 두 가지만 지켜도 논문 심사에서 **"시스템 설계의 완성도가 매우 높다"**는 평가를 받을 수 있습니다.

---

## 2. 지향해야 할 전체 프로젝트 구조 (Ideal vs. Practical)

OpenVLA의 구조를 단순화하여, 현재 프로젝트에 바로 적용 가능한 구조를 제안합니다.

```text
project_root/
├── agents/             # [Brain] 모델 로드 및 추론
│   ├── vla_agent.py    # OpenVLA 관련 로직 (Processor + Model)
│   └── base_agent.py   # 추상 클래스 (인터페이스 정의)
├── controllers/        # [Translator] 액션을 로봇 명령으로 변환
│   ├── ik_ctrl.py      # 현재 구현 중인 IK 제어기
│   └── rola_ctrl.py    # 추후 구현할 RoLA 제어기
├── envs/               # [World] 시뮬레이션 환경 (Genesis)
│   └── genesis_env.py  # 씬 구성, 로봇 로드, 카메라 렌더링
├── configs/            # [Settings] 하이퍼파라미터 관리 (YAML 등)
│   └── base_config.py  # Scaling factor, 지연 시간 설정 등
└── main_eval.py        # [Entry] 전체 실험 루프 및 데이터 저장
```

---

## 3. 현재 `vla_sim.py` 모듈화 단계 (Step-by-Step)

현재의 단일 스크립트 코드를 다음과 같이 3대 핵심 클래스로 분리하는 작업부터 시작하세요.

### Step 1: `VLAAgent` 클래스 (추론부 분리)
*   **역할**: 이미지와 명령어를 받아 `action` (7차원 토큰)을 반환.
*   **모듈화 포인트**: 모델 로딩과 `predict_action` 로직을 이 안에 넣으세요. 나중에 모델을 바꿔도 이 클래스 인터페이스만 맞추면 됩니다.

### Step 2: `IKController` 클래스 (제어부 분리)
*   **역할**: VLA의 델타 값을 받아 `Inverse Kinematics`를 수행하여 관절각 출력.
*   **모듈화 포인트**: `Action Scaling`, `Coordinate Transform (R_cam_to_base)`, `Smoothing (EMA)` 로직을 이 클래스의 메서드로 만드세요. **여기가 논문의 핵심 기여(Contribution) 부분이 될 것입니다.**

### Step 3: `GenesisEnv` 클래스 (환경부 분리)
*   **역할**: Genesis 엔진 초기화 및 로봇 제어 명령 전달.
*   **모듈화 포인트**: `scene.step()`을 몇 번 돌릴지(Sub-stepping), 카메라 위치는 어디인지 등을 관리합니다.

## 4. 논문 실험을 위한 핵심 "치트키": Latency Injector

논문에서 "지연 시간에 따른 성공률"을 측정하려면, 시스템 구조상 **지연 시간을 임의로 조절할 수 있는 장치**가 필요합니다.

*   **구현 방법**: `main_eval.py` 루프에서 한 사이클이 돌 때마다 `time.sleep(target_latency)`를 추가하는 간단한 코드를 넣으세요.
*   **모듈화의 이점**: 모듈화가 잘 되어 있으면, `Agent`의 추론 시간과 `Controller`의 계산 시간을 별도로 측정하여 **"어느 구간에서 병목이 발생하는지"** 분석하는 차트를 논문에 넣을 수 있습니다.

3.  **엄격함의 정도**: OpenVLA처럼 복잡한 레지스트리 패턴까지는 필요 없습니다. 단순히 클래스로 나누고, 생성자(`__init__`)에서 파라미터를 받는 수준이면 충분합니다.

이렇게 구조를 잡고 시작하면, 나중에 **RoLA를 추가할 때 `controllers/` 폴더에 파일 하나만 더 만들면 되는** 마법 같은 경험을 하시게 될 것입니다.
