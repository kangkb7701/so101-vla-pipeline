# 실험계획서: SO-101에서 행동 표현에 따른 VLA 파인튜닝 성능 비교

작성일: 2026-09-26
대상 학회: 한국정보통신학회 2026 추계종합학술대회 (요약문 제출본 기준)

## 1. 연구 질문

저비용 로봇 SO-101에서, 사전학습된 VLA를 파인튜닝할 때 **출력 행동 표현만 바꾸면** 성공률과 실패 유형이 어떻게 달라지는가.
최근 연구는 상대 표현이 절대 표현보다 낫다고 보고하지만, 관절 측정값과 실제 자세의 오차가 큰 저비용 로봇에서도 그런지 검증한다.

비교할 행동 표현 네 가지:

- 절대 관절각: 다음 목표 관절각 그대로 (6차원: 관절 5 + 그리퍼 1)
- 관절 상대 변위: 청크 시작 시점의 현재 관절각 기준 차이 (6차원)
- 절대 엔드이펙터 자세: 로봇 베이스 좌표계 기준 위치와 방향 (10차원: 위치 3 + 6D 회전 6 + 그리퍼 1)
- 상대 엔드이펙터 변환: 청크 시작 시점의 현재 엔드이펙터 자세 기준 변환 (10차원, 형식 동일)

그리퍼는 네 표현 모두 절대값으로 둔다.

## 2. 확정된 실험 설정 요약

- 모델: SmolVLA, π0.5 (여유 시 X-VLA 추가)

- 파인튜닝: 각 모델의 공식(lerobot 문서) 방식을 따르되 네 표현에 동일 적용, 체크포인트는 마지막 것. π0.5는 공식 방식(전체 학습)이 24GB에 들어가지 않아 저메모리 방식 선택 필요
- 평가: 조건당 20회, 성공 기준·실패 유형 사전 정의, 제한 시간 60초

## 4. 모델

**확정 범위: SmolVLA와 π0.5.** 두 모델로 네 표현을 전부 돌린다.

- **SmolVLA** (`lerobot/smolvla_base`, 약 4.5억): SO-100/101 커뮤니티 데이터로 사전학습. 풀 파인튜닝이 여유 있게 되고 학습이 빨라 주 실험 모델.
- **π0.5** (`lerobot/pi05_base`, 약 30억): 성능 기준점. 공식 방식은 전체 학습(bf16, gradient checkpointing, 배치 32)이지만 24GB에서 메모리 부족으로 실패했다(9절 점검 결과). action expert만 학습 또는 LoRA 중 선택이 필요하다. 관절 상대 표현이 플래그로 지원된다.

선정 근거와 한계:

- 두 모델은 크기가 약 4.5억과 약 30억으로 달라, 같은 경향이 나오면 특정 모델에 한정된 결과라는 반론을 막을 수 있다.
- 약점: 두 모델 모두 주로 관절 공간에서 사전학습됐다. 엔드이펙터 표현이 낮게 나와도 "저비용 로봇이라서"인지 "사전학습 표현과 달라서"인지 구분할 수 없다. 논문에 한계로 명시한다.
- 시간이 남으면 **X-VLA** (`lerobot/xvla-base`, 약 9억)를 세 번째로 추가한다. 엔드이펙터 공간에서 사전학습된 모델이라 위 두 원인을 가르는 대조군이 된다. 공정성을 위해 네 표현 모두 `action_mode=auto`로 학습한다.
- GR00T N1.5는 π0.5와 역할(30억급 대형 모델)이 겹쳐 제외한다. 참고로 이 장비에서 과일 태스크로 학습한 기록이 있다(`outputs/train/groot_so101_pick_place_fruit_flash_50k`).

다운로드 상태 (2026-09-27 재확인):

- 받음: `lerobot/smolvla_base`, `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`, `lerobot/pi05_base`, `lerobot/xvla-base`, `facebook/bart-large`, `nvidia/GR00T-N1.5-3B`, `lerobot/eagle2hg-processor-groot-n1p5`
- `google/paligemma-3b-pt-224` 토크나이저(π0.5용, gated): 라이선스 동의 후 받음
- `lerobot/pi05_base` 이전 리비전 `a538eb27`: `smoke/pi05_base_rev_a538eb27` (현재 lerobot과 호환, 가중치 동일)

모델별 카메라 연결(`--dataset.rename_map`):

- SmolVLA: top → `camera1`, wrist(측면) → `camera2`
- π0.5: top → `base_0_rgb`, wrist(측면) → `left_wrist_0_rgb`
- X-VLA: top → `image`, wrist(측면) → `image2`

세 번째 카메라가 없는 경우 빈 이미지로 처리되는 것을 코드에서 확인했다.

주의: 학습 때는 `--rename_map`으로 연결하면 되지만, 이 버전의 `lerobot-record`는 모델을 불러올 때 rename_map을 모델 쪽에 넘기지 않아(`lerobot_record.py:562`) 카메라 이름 불일치 에러로 멈춘다. 로봇 설정에서 카메라 이름 자체를 모델 쪽 이름(예: `camera1`, `camera2`)으로 지정하면 코드 수정 없이 동작한다(9절 점검 결과).

## 5. 데이터셋

**확정: `data/lerobot/so101_pick_place_fruit`의 파일 000~005**, 180 에피소드, 34,382 프레임 (파랑·노랑·초록 바구니에 바나나 옮기기, 색깔별 60개).
파일 006~007은 초록 바구니만 추가된 것이라 편향을 막기 위해 제외한다. 이전 ACT·Octo 실험과 같은 구성이다.

데이터 특성 (측정값):

- 10fps로 녹화됨(영상 파일도 10fps). 30fps로 바꿀 원본이 없으므로 10Hz로만 쓸 수 있다.
- 에피소드 평균 189프레임(약 19초)
- 행동 라벨은 조종기(leader) 명령값, 상태는 follower 측정값, 둘 다 6차원(관절 5개 + 그리퍼)
- 명령값과 다음 프레임 측정값의 차이: 팔 관절 평균 1~2°, 그리퍼 평균 약 3.7°(물체를 쥘 때 생기는 정상적인 차이)
- wrist_roll이 에피소드마다 크게 흩어져 있다(행동값 5~95% 구간 -169.5° ~ +12.9°). 녹화 중 손목이 흘러간 것이고 태스크 성공과 무관하다.

**wrist_roll 처리 (확정, 2026-09-27): 기록된 그대로 쓴다.** 이전 안(학습 라벨에서 빼고 실행 시 중앙값 -48.0°로 고정)은 쓰지 않는다. 그대로 쓰면 데이터 가공이 없어 표준적이고, 손목 방향은 영상에 보여 모델이 배울 수 있다. 대신 태스크와 무관한 흔들림까지 학습하게 된다.

## 6. 행동 표현 구현

공통 원칙: 네 조건 모두 **입력(`observation.state`)은 관절각으로 고정하고 출력(`action`)만 바꾼다.** 추론 결과는 공통 후처리로 절대 관절각으로 되돌려 로봇에 보낸다.

- **절대 관절각**: 추가 작업 없음. 모델 기본값이다.
- **관절 상대 변위**:
  - π0.5: `lerobot-edit-dataset --operation.type recompute_stats --operation.relative_action true`로 상대 행동 기준 통계를 다시 계산하고(청크 길이 15), 학습 때 `--policy.use_relative_actions=true`를 켠다. 통계 재계산을 빠뜨려도 에러 없이 학습이 돌아가므로 주의한다.
  - SmolVLA: 공용 변환 단계(`processor/relative_action_processor.py`)를 `processor_smolvla.py`에 π0.5와 같은 방식으로 연결한다.
- **절대 엔드이펙터 자세**: lerobot 순기구학(`model/kinematics.py`)과 URDF로 데이터셋의 `action` 열을 위치 3 + 6D 회전 6 + 그리퍼 1로 다시 쓰는 변환 스크립트를 만든다. 학습은 `lerobot-train` 그대로 된다.
- **상대 엔드이펙터 변환**: 위 변환에 더해, 청크 시작 시점 엔드이펙터 자세의 역변환을 곱해 상대 변환으로 만든다. 형식은 절대 엔드이펙터와 같은 10차원.
- **실행 스크립트**: `lerobot-record`는 로봇에 보내기 직전 처리가 기본값으로 고정돼 있어 역기구학을 넣을 수 없다. `examples/so100_to_so100_EE/evaluate.py`를 참고해 역기구학 단계(`InverseKinematicsEEToJoints`)를 포함한 SO-101용 공통 실행 스크립트를 하나 만들고, 조건에 따라 후처리만 바꾼다. 절대 관절각에서는 후처리가 아무 일도 하지 않는다.

### 회전 표현 (확정: 6D 회전)

방향을 각도 3개(오일러 각)로 적으면 180°에서 -180°로 값이 튀는 구간이 있어 학습이 불안정하다. 6D 회전은 그리퍼 앞쪽이 가리키는 방향(3)과 윗면이 가리키는 방향(3)을 화살표로 적는다. 세 번째 방향은 이 둘에서 계산된다. 튀는 구간이 없어 절대 자세 표현에 주로 쓰인다(Diffusion Policy 실제 로봇 실험, UMI, X-VLA, RDT-1B).

두 엔드이펙터 표현 모두 6D로 통일한다. 회전 적는 방식까지 다르면 결과 차이가 "절대 대 상대" 때문인지 구분할 수 없기 때문이다. 이전 Octo 실험의 7차원(위치 변화 3 + 오일러 각 변화 3 + 그리퍼 1, 직전 step 기준 누적형)과는 회전 적는 방식과 델타 기준점이 모두 다르다.

### 도달 불가능 자세 처리 (확정)

SO-101은 관절이 5개(wrist_roll 고정 시 4개)라, 모델이 예측한 엔드이펙터 자세 중 팔이 물리적으로 만들 수 없는 것이 나온다. 역기구학이 이를 관절각으로 바꿀 때 다음 규칙을 따른다.

- 위치 우선: 위치 가중치 1.0, 방향 가중치 0.01 (lerobot `RobotKinematics.inverse_kinematics` 기본값). 잡고 놓는 데는 위치가 방향보다 중요하다.
- 관절 한계로 자르기: 계산된 관절각이 모터 범위를 넘으면 한계값까지만 보낸다.
- 솔버 실패 시 직전 관절값 유지.
- 오차 기록: 목표 자세와 실제로 만든 자세의 위치·방향 차이를 매 step 저장한다. 엔드이펙터 표현이 실패했을 때 모델 예측 문제인지 역기구학 문제인지 구분하는 데 쓴다.

## 7. 변인통제

### 표현에 따라 필연적으로 바뀌는 것 (규칙을 정해 명시)

- 정규화 통계: 표현별로 따로 계산하되 방식은 하나로 통일한다.
- 역기구학 오차와 지연: 엔드이펙터 표현에만 생긴다. 위 처리 규칙을 고정하고 오차를 따로 보고한다.
- 사전학습과의 궁합: 두 모델 모두 주로 관절 공간에서 사전학습됐다. 결과를 모델과 표현의 상호작용으로 해석한다.

### 반드시 고정할 것

- 데이터: 같은 에피소드 목록. 학습/검증 분할을 파일로 저장한다.
- 하이퍼파라미터: 학습률과 배치는 각 모델의 lerobot 기본값을 그대로 쓰고, 네 표현에 똑같이 적용한다. 표현마다 따로 튜닝하지 않는다.
- 에폭 수: SmolVLA 절대 관절각 기준선 학습 결과를 보고 한 번 정한 뒤 네 표현에 똑같이 적용한다. step 수는 "에폭 × 34,382 ÷ 배치"로 모델마다 계산한다.
- 체크포인트: 마지막 체크포인트를 쓴다. 결과를 보고 고르지 않는다.
- 청크: **15 step 예측(1.5초).** 실행 step 수는 5, 10, 15 중 사용자가 결정한다.
  - 청크 길이는 step 수가 아니라 시간으로 봐야 한다. 기본값 50은 π0.5 사전학습 주기(주로 50Hz) 기준 약 1초, SmolVLA 사전학습 주기(주로 30fps) 기준 약 1.7초다. 이 데이터는 10Hz라 50이면 5초가 되어 너무 길다. 15 step(1.5초)은 원래 시간 길이에 가깝다. 참고로 Diffusion Policy는 같은 10Hz에서 16 step 예측·8 step 실행을 썼다.
  - 상대 표현은 청크 시작 시점 상태를 기준으로 하므로 청크 길이가 표현 간 차이에 직접 영향을 준다. 반드시 고정한다.
- 상대 표현 기준점: 청크 시작 시점 상태(청크 단위 델타). 청크 안의 모든 step이 같은 기준점에서의 차이다. lerobot 구현(`to_relative_actions`)이 이 방식임을 코드로 확인했다. 직전 step 기준의 누적형 델타는 쓰지 않는다.
- 제어 주기: 10Hz. 모델에 고유 fps는 없고 파인튜닝 데이터의 주기를 따른다. π0.5도 10Hz인 LIBERO 데이터로 파인튜닝해 좋은 성능을 낸 사례가 있다.
- 행동 보간(`interpolation_multiplier`): 사용하지 않는다. 동작이 끊겨 실패가 생기면 네 조건 모두 똑같이 켠다.
- 실행 환경: GPU, 캘리브레이션 파일, 카메라 위치(기준 프레임과 대조, 바닥에 테이프로 표시), 조명, 안전 제한값.

- 제한 시간: 60초(데이터 평균 19초의 약 3배).
- 실패 유형: 잡기 실패, 옮기다 놓침, 다른 바구니, 충돌·이상 동작, 시간 초과.
- 실행 순서: 조건을 섞어서 돌린다. 한 조건을 몰아서 돌리면 서보 발열, 조명, 시간대 차이가 표현 차이로 둔갑한다.
- 기록: 모든 시행을 영상으로 남긴다.
- 통계: 성공률에 Wilson 신뢰구간, 위치별 짝 비교 검정.

## 9. 사전 점검 결과 (2026-09-27, 하드웨어 미연결 상태)

검증 방법: `smoke/offline_policy_check.py`는 `lerobot-record`가 모델을 다루는 부분(`make_policy` → `make_pre_post_processors` → `predict_action` → `make_robot_action`)을 그대로 쓰고, 로봇·카메라 입력만 데이터셋 녹화 프레임으로 바꿔 넣는다. 로봇 연결, 카메라 캡처, 실제 동작은 하드웨어 연결 후 확인해야 한다.

SmolVLA (절대 관절각, 300 step 짧은 학습, `smoke/smolvla_abs_300`):

- 학습: 정상 완료. 배치 64에서 step당 약 0.95초, GPU 약 13.4GB.
- 체크포인트에 가중치·설정·전처리/후처리(정규화 통계 포함)가 함께 저장되고, 실행 경로로 불러와 관절 6개 각도 출력까지 정상 동작.
- 추론: 청크 1회 예측 약 300ms, 큐에서 꺼내는 step은 약 3ms. 10Hz 제어에 충분하다.
- 에피소드 5의 45 step 기준 정답 대비 평균 오차: 어깨 들기·팔꿈치 약 11°, 나머지 3° 이하 (300 step만 학습한 상태라 성능 지표가 아님).
- 발견한 문제: `lerobot-record`가 모델을 불러올 때 rename_map을 넘기지 않아 카메라 이름 불일치로 멈춘다. 로봇 카메라 이름을 모델 쪽 이름(`camera1`, `camera2`)으로 지정하는 방식으로 코드 수정 없이 동작함을 확인했다.
- 설치: lerobot 환경에 빠져 있던 SmolVLA 의존성 `num2words`를 설치했다(lerobot `smolvla` 추가 의존성에 포함된 패키지).

π0.5 (배치 32, 20 step 메모리 측정, `smoke/pi05_memory_test.sh`):

- 전체 학습(공식 방식, 학습 파라미터 41억): 메모리 부족으로 실패.

- 학습 방식 옵션은 `--policy.type` 대신 `--policy.path`로 불러와야 카메라 이름 변환이 적용된다.

기타:

- 오늘 받아 둔 HF 캐시 중 `pi05_base`, `xvla-base`, `eagle2hg-processor`가 중간에 비어 있었다(원인 미확인). 다시 받았다.
- 데이터셋 정규화 통계(`meta/stats.json`)는 파일 000~007 전체 240 에피소드 기준으로 계산돼 있고, 학습은 180 에피소드만 쓴다.

최신 lerobot(main, 2026-09-25 커밋 e595b7902) 확인 사항:

- 새 문서 `docs/source/action_representations.mdx`가 이번 연구의 표현 구분(절대/청크 단위 상대/step 단위 델타, 관절/엔드이펙터)을 UMI(Chi et al., 2024) 용어로 정리하고 있다. 논문 용어를 이 문서와 맞추면 좋다.
- 이 문서에서 엔드이펙터 상대 표현은 값별 뺄셈(현재 엔드이펙터 값과의 차이)으로 설명한다. 이 계획서의 정의(청크 시작 시점 자세의 역변환을 곱하는 방식)와 다르다(11절 미결정).
- SmolVLA는 최신판에도 관절 상대 표현 옵션이 없다(설정에 `use_delta_joint_actions_aloha`만 있음). 계획대로 전처리에 연결하는 코드가 필요하다.
- SO-101 전용 출력 어댑터는 없다. ACT는 출력층을 데이터셋 행동 차원(6)에 맞춰 새로 만들고, SmolVLA·π0.5는 행동을 32차원까지 0으로 채운 뒤 공용 입출력 투영층(`action_in_proj`, `action_out_proj`)으로 처리한다. 이 투영층은 파인튜닝 때 함께 학습된다.

π0.5 학습 시간 분석 (2026-09-27):

- 느린 이유: step마다 샘플당 약 970토큰(이미지 3칸 × 256 + 텍스트 200칸)을 20억 파라미터 언어모델과 action expert에 통과시키고, gradient checkpointing으로 역전파 때 앞 계산을 한 번 더 한다. 측정 시 컴파일(`compile_model`)은 꺼져 있었다. 3090에서 step당 약 10초는 연산량상 정상 범위다.
- 낭비되는 계산(약 3분의 1): 카메라가 2대라 세 번째 이미지 칸은 빈 이미지인데도 256토큰을 계산한다(가려지기만 함). 실제 텍스트는 146토큰(태스크 문장 + 상태 숫자)인데 200칸까지 채운다.
- 속도 선택지(미결정): 컴파일 켜기(공식 문서 예시 설정), 텍스트 길이를 146 이상으로 줄이기, 빈 카메라 칸 없애기(사전학습 입력 구조와 달라져 표준에서 벗어남).
- lerobot의 π0.5 LoRA 기본값은 action expert의 attention(q, v)과 입출력층만 학습해 약 130만 파라미터뿐이다. openpi 공식 LoRA는 언어모델에도 LoRA를 붙이는 방식이라 이름만 같고 내용이 다르다.
- 본 학습 전 필수: 최종 설정으로 짧은 예비 학습(예: 300 step)을 돌려 손실 감소와 체크포인트 실행 경로를 확인한 뒤 본 학습을 시작한다. π0.5 본 학습 기회는 한 번뿐이다.

정규화 통계 점검 (2026-09-27):

- 기존 `meta/stats.json`은 240 에피소드 기준이다. 평균·표준편차는 180 에피소드 값과 거의 같다(차이는 wrist_roll 평균 -71.3° 대 -64.7° 정도).
- 분위수(q01, q99)는 실제 분포와 크게 다르다. 180 에피소드 프레임 중 저장된 q01~q99 범위를 벗어나는 비율이 관절별로 18~75%다(정상이라면 약 2%). 예: wrist_roll 저장값 -93° ~ -44°, 실제 1~99% 범위 -188° ~ 62°. 원인은 확인하지 않았다.
- 영향: SmolVLA는 평균·표준편차로 정규화해서 영향이 작다. π0.5는 기본이 분위수 정규화라 값 대부분이 정상 범위 밖으로 밀려나고, 상태를 [-1, 1] 구간 256칸으로 나눠 텍스트로 넣는 단계에서 잘릴 수 있다.

예상 학습 시간 (위 측정값 기준, GPU 1장 연속 가동):

- SmolVLA: 공식 예시(20,000 step, 배치 64, 약 37 에폭) 기준 1회 약 5.3시간. 4 표현 × 시드 3개 = 12회면 약 64시간.
- π0.5: lerobot 문서 예시(3,000 step, 배치 32, 약 2.8 에폭) 기준 1회 약 9시간(LoRA 배치 32, 또는 expert만 학습 배치 16으로 6,000 step). 4 표현 = 약 36시간. SmolVLA와 같은 에폭(약 37)으로 맞추면 1회 약 120시간이라 현실적으로 불가능하다.
- 합계(시드 3개 기준): 약 100시간. 데이터 변환·평가 시간은 제외. `compile_model` 사용 시 속도 변화는 측정하지 않았다.

## 9-1. π0.5 파인튜닝 분석 (2026-09-27, 최신 lerobot)

환경: `~/lerobot-main` (기존 저장소의 git worktree, 커밋 e595b7902, 2026-09-25로 고정), conda 환경 `lerobot_main` (Python 3.12, torch 2.11.0+cu130, transformers 5.5.4, peft 0.21.0). 설치 패키지 목록: `env_lerobot_main_freeze.txt`. 기존 `~/lerobot`과 `lerobot` 환경은 그대로 둔다. 로봇 키보드 입력용 `evdev` 빌드가 실패해 `hardware` 추가 의존성은 아직 설치하지 않았다(로봇 실행 전 처리).

최신 버전에서 해결된 것:

- Hub 최신 `lerobot/pi05_base`가 그대로 로드된다(이전 리비전 우회 불필요).

공식 파인튜닝 설정 비교:

- openpi(π0.5 원 저자 코드): 전체 학습, 배치 32, 20,000~30,000 step(`pi05_droid_finetune` 20,000 step·청크 16, 기본값 30,000 step). 저메모리용 공식 LoRA는 언어모델(gemma_2b_lora)과 action expert(gemma_300m_lora) 모두에 LoRA를 붙인다.
- lerobot 문서: 전체 학습, 배치 32, 예시 3,000 step. lerobot 기본 학습률 일정은 최고 2.5e-5, warmup 1,000, 감쇠 30,000 step이며 step 수가 더 적으면 비율대로 줄어든다.
- 이 PC에서 전체 학습은 옵티마이저 상태만으로 24GB를 넘어 어떤 배치로도 불가능하다.

측정 결과 (30~60 step, bf16, gradient checkpointing 켬):

- action expert만 학습 (학습 파라미터 6.9억): 배치 16에서 최대 20.0GB, step당 5.47초(샘플당 0.34초).
- 같은 설정 + 컴파일: 최대 19.5GB, step당 3.19초(샘플당 0.20초, 약 1.7배 빠름). 첫 step 컴파일에 약 55초.
- 같은 설정 + 텍스트 길이 160: step당 5.39초(효과 약 1.5%, 무시할 수준).
- 같은 설정 + gradient checkpointing 끔: 배치 16·32 모두 메모리 부족.
- lerobot 기본 LoRA (action expert attention q·v와 입출력층, 학습 파라미터 약 135만): 배치 32에서 최대 23.2GB, step당 10.83초(샘플당 0.34초).
- openpi 방식 LoRA (언어모델 + action expert의 attention·MLP, r=16, 학습 파라미터 약 2,664만): 배치 32는 메모리 부족, 배치 16에서 최대 19.2GB, step당 7.53초(샘플당 0.47초). 컴파일을 켜면 배치 16에서 메모리 부족.

학습량별 1회 예상 시간 (표현 4개면 ×4):

- lerobot 문서 예시 분량(샘플 9.6만 개, 약 2.8에폭): expert만+컴파일 약 5.3시간, expert만 약 9.1시간, openpi 방식 LoRA 약 12.5시간.
- openpi `pi05_droid_finetune` 분량(샘플 64만 개, 약 18.6에폭): expert만+컴파일 약 36시간, openpi 방식 LoRA 약 84시간.
- openpi 기본 분량(샘플 96만 개, 약 28에폭): expert만+컴파일 약 53시간.

해석:

- π0.5 원 저자의 표준(전체 학습 + 2만~3만 step)은 이 장비에서 메모리와 시간 모두 불가능하다. 어떤 선택을 해도 표준에서 벗어나므로, 무엇을 바꿨는지 논문에 명시해야 한다.
- 방식별 성격: expert만 학습은 언어모델·비전을 고정해 카메라 영상 해석은 사전학습 그대로 두고 행동 생성부만 학습한다. openpi 방식 LoRA는 원 저자의 공식 저메모리 방식이며 언어모델도 조금 적응시킨다. lerobot 기본 LoRA는 학습 파라미터가 가장 적어(약 135만) 적응 폭이 가장 작다.
- 샘플당 속도는 expert만과 lerobot 기본 LoRA가 같고, 컴파일은 expert만 학습에서만 메모리 안에 들어갔다.
- 텍스트 길이 축소는 효과가 거의 없다. 빈 카메라 칸 제거는 측정하지 않았다(사전학습 입력 구조가 바뀜).

SmolVLA 속도 재측정 (2026-09-27, 최신 lerobot, 배치 64, 청크 15, `smoke/smolvla_speed_test_main.sh`):

- 기본: step당 0.913초, 최대 15.1GB. 공식 예시 20,000 step이면 1회 약 5.1시간, 표현 4개 약 20.3시간.
- 컴파일(`compile_model=true`): step당 0.739초(약 1.24배), 최대 13.3GB. 1회 약 4.1시간, 표현 4개 약 16.4시간.

- 학습: SmolVLA, 절대 관절각, `--steps=20000`(약 37에폭), 체크포인트 5,000 / 10,000 / 15,000 / 20,000 step 저장.
- 평가: 네 체크포인트를 실제 로봇에서 각 30회 평가한다(보수적 판정을 위해 본 평가의 20회보다 늘림). 같은 물체 위치 목록과 바구니 배정을 쓰고, 체크포인트 순서는 섞어서 실행한다.
- 판정 규칙(보수적, 학습을 너무 일찍 끊지 않는 방향):
  - 가장 높은 성공률을 "최고값"으로 둔다.
  - 최고값에서 10%p(30회 중 3회) 이내인 체크포인트 중 가장 이른 것을 후보로 둔다.
  - 후보 이후의 모든 체크포인트가 후보보다 10%p 넘게 높지 않을 때만 후보를 채택한다. 그렇지 않으면 다음 체크포인트로 넘어가 같은 검사를 반복한다.
  - 애매하면 더 늦은 체크포인트를 고른다. 20,000 step이 가장 높고 차이가 10%p를 넘으면 20,000 step을 쓴다(학습 부족 가능성으로 기록).
  - 보조 지표로 학습 손실 곡선이 평평해졌는지도 함께 확인한다.
- 주의(학습률 일정): lerobot은 전체 step 수에 맞춰 학습률 감소 일정을 늘이고 줄인다(`optim/schedulers.py`). 그래서 20,000 step 학습의 10,000 step 체크포인트는 "10,000 step짜리 학습"과 다르다. 나머지 세 표현도 `--steps=20000`으로 같은 일정을 쓰고, 채택한 step에서 저장된 체크포인트를 쓴다(그 뒤 학습은 중단 가능). 절대 관절각은 기준선 학습의 체크포인트를 그대로 본 실험에 쓴다.
- 기준선 평가는 실제 로봇이 필요하다(체크포인트당 30회, 합계 120회).
- 기준선 학습 시작 전 필요한 결정: 정규화 통계(240 대 180 에피소드). wrist_roll(기록 그대로)과 컴파일(사용)은 2026-09-27 결정.

## 9-5. 로봇 실행 스크립트 (2026-09-27)

`eval/eval_rollout.py`: lerobot 공식 `lerobot-rollout`을 그대로 실행한다(명령줄 옵션 동일). 체크포인트가 엔드이펙터 정책(행동 10차원)이면, 불러온 정책의 후처리 끝에 역기구학 단계를 붙여 정책이 관절 6개 명령을 내보내게 한다. 그래서 실행·녹화·영상 저장은 네 표현 모두 같은 공식 루프를 쓴다(`eval/ee_ik_steps.py`).

- 역기구학 규칙: lerobot `RobotKinematics.inverse_kinematics`, 위치 가중치 1.0 / 방향 가중치 0.01, 초기값 = 현재 측정 관절값, 관절 한계로 자르기, 해가 비정상이면 현재 관절 유지, 매 step 목표 대비 위치(mm)·방향(°) 오차를 CSV로 기록(`$EE_IK_LOG`).
- 발견한 lerobot 문제: `inverse_kinematics`가 초기 관절값을 넣은 뒤 기구학 상태를 갱신하지 않아, 직전 호출 자세를 기준으로 풀기 시작한다. 연속 호출 시 약 23%가 크게 틀렸다. 호출 직전에 순기구학으로 상태를 갱신하도록 처리했다(lerobot 코드는 수정하지 않음).
- 관절 한계 문제: 실제 로봇은 URDF 관절 한계를 넘어 움직였다(녹화 행동 중 shoulder_lift 15%, wrist_flex 28%, wrist_roll 7.5%가 한계 밖). 정답 엔드이펙터 목표를 역기구학으로 풀었을 때(`eval/check_ik_on_gt.py`, 2,000 프레임):
  - URDF 한계 사용(`EE_IK_JOINT_LIMITS=urdf`, 기본값): 한계 안 목표는 오차 0mm, 한계 밖 목표는 상위 5% 15mm·최대 23mm. 전체 상위 5% 10.5mm.
  - 녹화 범위 사용(`EE_IK_JOINT_LIMITS=data`): 1,995프레임 정확 복원(상위 5% 0mm), 범위 끝에서 잘린 5프레임(0.25%)만 오차.
- 하드웨어 없는 전체 경로 시험(`eval/test_rollout_offline.py`): 녹화 에피소드를 재생하는 가짜 SO-101로 실제 `lerobot-rollout` 경로를 돌렸다. 에피소드 5, 15초, 녹화 행동과의 관절별 평균 오차(°):
  - 절대 관절각(최종): 1.3 / 4.4 / 3.4 / 1.9 / 2.0, 그리퍼 0.4
  - 관절 상대(최종): 1.1 / 3.9 / 1.8 / 1.5 / 1.1, 그리퍼 0.5
  - 절대 엔드이펙터(10,000 step 중간 체크포인트): 1.4 / 3.8 / 5.1 / 2.8 / 1.5, 그리퍼 0.4. 역기구학 평균 오차 위치 0.9mm, 방향 0.7°, 자르기·실패 0회.
  - 참고: `lerobot-rollout`은 종료 시 로봇을 시작 자세로 되돌리는 명령을 보낸다(평가 기록에서는 제외해야 함).

실행 예시 (카메라 이름을 모델 쪽 이름으로 지정하거나 `--rename_map` 사용):

```
cd 2026-09-paper/eval
~/anaconda3/envs/lerobot_main/bin/python eval_rollout.py --strategy.type=base \
  --policy.path=../runs/smolvla_abs_ee/checkpoints/012893/pretrained_model \
  --robot.type=so101_follower --robot.port=/dev/ttyACM1 --robot.id=my_follower \
  --robot.cameras="{camera1: {type: opencv, index_or_path: <상단>, width: 640, height: 480, fps: 30}, camera2: {type: opencv, index_or_path: <측면>, width: 640, height: 480, fps: 30}}" \
  --task="pick the banana and place it in the blue basket" --duration=60 --fps=10
```

π0.5는 카메라 이름을 `base_0_rgb`(상단), `left_wrist_0_rgb`(측면)로 쓴다. 실행 step 수는 `--policy.n_action_steps=<5|10|15>`로 바꾼다. 로봇 키보드 입력용 `evdev`는 아직 설치하지 않았다(`hardware` 추가 의존성).
